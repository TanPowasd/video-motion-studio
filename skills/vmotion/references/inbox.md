# Canvas requests (画布指令)

The person selects something on the Studio canvas and types what they want (Ctrl+Enter, the 问 AI button on the
selection toolbar, or Ctrl+K → 向 AI 发画布指令). Vmotion never calls a model: it stores the request with its context
and waits for you. You do the work by editing project files as usual, then report back.

## Where requests live

`.vmotion/requests/<id>.json` plus a frame snapshot `<id>.png` (≤ 960 px wide). Ids look like
`req-20261026-012300-ab12`. Status: `pending` → `claimed` → `done` | `question` | `cancelled`.
Do not edit these files by hand; use the CLI or MCP so the lock and the change linking work.

Useful context fields (`context`):

- `sceneId` (→ `scenes/<sceneId>.json`), `frame`, `seconds`, `fps`, optional `range {start,end}` in frames;
- `snapshot`: the PNG the person was looking at; open it before you change anything;
- `selection[]`: `id`, `name`, `type`, current `props`, canvas `bounds`; for nodes generated by a JSX component also
  `owner {nodeId, component}`, `localId` and `source {file, line, endLine}`: edit that `.tsx` range, keep ids stable;
- `revision` of the project when the request was made.

## Loop (CLI)

```bash
vmotion inbox wait --project . --timeout 20000     # claims the oldest pending request; request:null → call again
vmotion inbox get <id> --project .                 # full context + question/reply thread
# … edit components/*.tsx or scenes/*.json, then check:
vmotion validate --project .
vmotion frame --project . --frame <frame> -o check.png
vmotion inbox done <id> --project . --summary "Title 96→128 px, fill #ff8a3d" --files components/title-card.tsx
```

Unclear request? Ask instead of guessing; the Studio card shows a reply box:

```bash
vmotion inbox ask <id> --project . --question "放大到多少？128 还是 160？" --wait 20000
```

Without `--wait`, the answer comes back through `inbox wait` (reason `reply`) or `inbox get`.
Other commands: `vmotion inbox list --project . [--status open|all|pending|claimed|question|done|cancelled]`,
`vmotion inbox claim <id> --project .`.

## MCP

Tools in the `inbox` category (not in the default 10; use `tools_search {"category":"inbox"}`, then `tool_call` or
`tools_load`): `inbox_list`, `inbox_get`, `inbox_wait` (timeoutMs ≤ 25000), `inbox_claim`, `inbox_done`, `inbox_ask`
(waitMs ≤ 25000). They only touch `.vmotion/requests`: results carry `committed:false`.
`agent_guide {"topic":"inbox"}` prints the same loop.

## Rules

- Only one agent can claim a request; a second claim fails with `INBOX_STATE`. Do not retry someone else's.
- While a request is claimed, your file, CLI and MCP changes are tagged with its id in the change journal; at done
  they are attached to the request, so the person can review and undo the whole request in one click. Finish with
  done promptly so unrelated later edits are not linked.
- `inbox_done` first ingests edits still in the file-watcher debounce, unless the person paused AI edits (hold).
- Creating, replying to, cancelling and requeueing requests are Studio-only; you cannot do them.
